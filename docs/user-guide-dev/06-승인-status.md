# 6. 승인·status (프론트 한계)

## 이용자에게 보이는 것

- 성공 시 **“생성 요청이 완료”** toast  
- 폼 하단 운영 카피: 심사, 승인/반려, 평일 점심~저녁 처리  
- 마이너 첫 방문 모달: 중복 주제 반려, 메인 승격 시 매니저 권한 회수  

일반 유저 문서: [개설 심사와 결과](../user-guide-general/08-개설-심사와-결과.md)

## 프론트에 없는 것

- 신청 목록 / 대기 중 status 배지  
- 관리자 “승인” 버튼  
- mutation 응답 `status` 바인딩  

즉 **허가 처리는 백엔드·운영 프로세스**이고, SPA는 create + 안내 카피 수준.

## 구현 시 확장 아이디어 (미구현)

- `status` 를 toast/MY페이지에 매핑  
- pending 갤러리 폴링 또는 “내 신청” 쿼리  
- 반려 사유 전용 필드 표시
